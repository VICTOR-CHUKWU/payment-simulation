## BE-01-04 intake: Express app skeleton per service

**Classification:** feature-grade. It adds new HTTP endpoints, startup wiring and shutdown behaviour in all three services.

**What exists now**
- Each `services/*/src/main.ts` only re-exports a placeholder constant (`SHARED_PACKAGE_NAME`). There's no HTTP server and no NATS connection yet.
- `libs/shared` already has `loadConfig` and `baseConfigSchema` ([config.ts](libs/shared/src/config.ts)), plus `connectNats` ([nats.ts](libs/shared/src/nats.ts)).
- `.env.example` already has `AUTH_PORT`, `PAYMENT_PORT` and `NOTIFICATION_PORT`, but nothing reads them.

**Proposed scope**

1. **Dependencies**
   - Express 5.2.1. 5.3.0 is only 9 days old, which breaks the two-week rule.
   - `@types/express` 5.0.6.
   - supertest 7.3.1 and `@types/supertest` 7.2.1 as root dev dependencies.
   - Express goes in `libs/shared`, because the logger, error and auth middleware will live there later.

2. **Shared `health.ts`**
   - `healthRouter(checks)` serves two endpoints:
     - `GET /health/live` always returns 200 `{status:"ok"}`.
     - `GET /health/ready` runs the named checks and returns either 200 or 503, with `{status, checks:{nats:"ok"|"fail"}}`.
   - `natsCheck(nc)` fails if the connection is closed or draining, or if `nc.flush()` (a NATS ping round-trip) takes longer than 1s. The timeout catches the case where the client is reconnecting.

3. **Shared `shutdown.ts`**
   - `onShutdown({ server, tasks, timeoutMs = 10_000 })` runs on SIGTERM and SIGINT:
     - Calls `server.close()`. On Node 24 this also closes idle keep-alive sockets.
     - Then runs the cleanup tasks in order: stop timers, then `nc.drain()`.
     - Sets `process.exitCode` and lets the process exit on its own.
   - A safety timer, set with `.unref()`, forces `process.exit(1)` if shutdown hangs.
   - A second signal does nothing.
   - The core logic is a plain `shutdown()` function, so tests can call it without sending real signals.

4. **Per service: `app.ts` + `main.ts`**
   - `app.ts`: `createApp({ checks })` returns an Express app with the health router. supertest tests use this.
   - `main.ts` is the bootstrap:
     - `loadConfig(baseConfigSchema.extend({ <SVC>_PORT }))`
     - connect to NATS if the service needs it
     - `listen`
     - `onShutdown`
   - Dependencies per service:
     - **auth:** no NATS, since it publishes no events. Readiness has no checks.
     - **payment:** NATS.
     - **notification:** NATS. The SMTP check comes later, in BE-05-04.

5. **Failing fast**
   - Invalid config, or NATS unreachable at startup, makes the process throw and exit non-zero.
   - There's no wait-on-first-connect retry loop.

6. **Cleanup**
   - Remove `SHARED_PACKAGE_NAME` and the placeholder tests.

7. **Tests**
   - supertest per service for live/ready, covering 200 and 503 with a failing stub check.
   - Unit tests for `natsCheck` (closed, draining, slow flush) and for `shutdown()` (order of steps, timeout, a second signal).
   - No test needs Docker.

8. **Docs**
   - README: the health endpoints, the ports, and the sentence about failing fast on bad config.
   - ROADMAP: status changes.
   - OpenAPI waits for BE-01-09, which will register the health routes.

**Not included:** pino logging and request IDs (BE-01-05), the error middleware and 404 handler (BE-01-06), helmet/CORS (BE-02-04), Swagger (BE-01-09) and any NATS consumers.

**One gap until BE-01-05 lands:** there's no logger yet and `console` isn't allowed, so services won't print "listening on…" or log shutdown steps. Startup errors still show up as an uncaught exception with exit code 1. BE-01-05 adds the log lines.

**Choices I made for you, change any of them:**
- Endpoint paths are `/health/live` and `/health/ready`, not `/healthz` and `/readyz`.
- Shutdown is hand-written with Node built-ins, about 30 lines, rather than a library such as `@godaddy/terminus` or `http-terminator`.
- On startup, a NATS outage makes the service exit instead of waiting.

**Fixes that change scope:**

After about 20 seconds of NATS downtime, the service would stay live but never become ready again. The doc now has `connectNats` in `libs/shared/src/nats.ts` pass `maxReconnectAttempts: -1` so it keeps retrying. A service started while NATS is down still exits right away. This is a small change to a shared module that BE-01-04 didn't touch before.
- **Test packages move out of the root:** `supertest` and its types now go in each package's own dev dependencies, because Biome fails when a test imports a package its own `package.json` doesn't list. The services also need `@types/express` themselves, or `tsc` can't find types for `express`.

**Fixes for things that would otherwise break the build, tests or lint:**
- `healthRouter` and `createApp` need explicit return types (`Router` and `Express`), or `tsc -b` fails.
- The shutdown task loop needs one `biome-ignore` comment for `noAwaitInLoops`, because the tasks have to run in order.
- The `server` parameter is typed as `{ close(cb) }`, so the test stub typechecks without a cast.
- `ReadinessCheck` is now an `interface`, which Ultracite requires.
- `natsCheck` always resolves `false` when a check fails; it never rejects.
- Shared's `index.test.ts` gets deleted along with `SHARED_PACKAGE_NAME`.

**Other corrections:**
- The doc now says correctly that `server.close()` only closes connections that are idle at that moment. A request still running can delay shutdown by about 5 seconds, which is well inside the 10-second limit.
