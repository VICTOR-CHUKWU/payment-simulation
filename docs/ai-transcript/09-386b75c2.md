## BE-01-09 intake: OpenAPI and Swagger UI per service

**Classification:** feature-grade. It adds a new public surface (`/docs`), new dependencies and a pattern every later endpoint milestone must follow.

**Objective:** each service serves Swagger UI at `/docs` and its spec at `/docs/openapi.json`, built from Zod schemas. Protected routes can be called from Swagger through an **Authorize** button that takes a bearer JWT. Both routes exist only when `NODE_ENV=development`.

### What the code does today
- Each service's `createApp({ checks, logger })` mounts the logger, the health routes, the 404 handler and the error handler, in that order ([services/auth/src/app.ts](services/auth/src/app.ts)). All three services have the same file.
- `NODE_ENV` is already checked by `baseConfigSchema` (`development | test | production`, default `development`) ([libs/shared/src/config.ts](libs/shared/src/config.ts)).
- The shared lib already has a Zod `problemDetailsSchema` for errors, so it can become the spec's shared error schema ([libs/shared/src/errors.ts:5](libs/shared/src/errors.ts#L5)).
- There is no auth middleware yet (that's BE-02-03) and no protected route yet (the first is BE-03-02).
- The current packages fit together: `@asteasolutions/zod-to-openapi@9.1.0` works with `zod ^4`, and schemas can be named with `.meta({ id })`, so Zod doesn't need patching. `swagger-ui-express@5.0.1` works with Express 5.

### Proposed scope
**New shared module `libs/shared/src/openapi.ts`:**
- `createOpenApiRegistry()`: a new registry with three things already in it: the `ProblemDetails` error schema, a `bearerAuth` scheme (`http`, `bearer`, `JWT`) and the two health paths.
- Helpers for later milestones:
  - `bearerSecurity`, which adds `[{ bearerAuth: [] }]` to a route.
  - `problemResponses(400, 401, 403, …)`, which builds `application/problem+json` error responses. This covers the rule that every route documents its errors.
- `buildOpenApiDocument(registry, { title, version })`: OpenAPI 3.1, with `servers: [{ url: "/" }]` so the spec works on any port.
- `docsRouter(document)`: serves `/docs` and `/docs/openapi.json`. The Swagger UI settings:
  - `persistAuthorization: true`, so the token survives a page reload
  - `tryItOutEnabled: true`
  - `displayRequestDuration: true`

**Each service:**
- A new `src/openapi.ts` that builds its document from a fresh registry. Later endpoint milestones add their routes there.
- `createApp` gets a `docs: boolean` option and mounts `docsRouter` before the 404 handler when it is true.
- `main.ts` passes `docs: config.NODE_ENV === "development"`.

**How you'd use auth in Swagger, once BE-02-02 lands:**
1. Open `localhost:3001/docs` and run `POST /auth/login`.
2. Copy `accessToken` from the response.
3. Open `localhost:3002/docs`, click **Authorize** and paste the token. Swagger then sends `Authorization: Bearer …` on every protected route.

Each port is a separate browser origin, so you paste the token once per service. After that it survives reloads.

### Decisions (recommended option first)
1. **Swagger UI package:** `swagger-ui-express` (recommended; it's the standard choice and handles the static assets) or serving `swagger-ui-dist` by hand (one fewer dependency, more code to maintain).
2. **Where the UI lives:**
   - **One UI per service on its own port (recommended).** Requests stay on the same origin, so no CORS is needed. The cost is pasting the token into each service.
   - **One combined UI with a spec dropdown.** One token covers all services, but it needs CORS on every service now and absolute server URLs. That pulls in part of BE-02-04.
3. **How "development only" works:** an explicit `docs` flag on `createApp`, set by `main.ts` (recommended). Tests can then check both the on and off cases without changing env vars. When docs are off, `/docs` returns the standard problem+json 404.
4. **What gets documented now:** the health endpoints and the `bearerAuth` scheme (recommended). The scheme is defined now even though no route uses it until BE-03-02, so the Authorize button is in place from the start.
