### Claude

I added the two lookups to the shared repository, and the seed now uses `users.findOneBy({ email })` instead of taking the first item from `find`. `pnpm check`, `pnpm typecheck`, `pnpm test` (219 passing) and `pnpm build` all pass, and nothing is committed.

```ts
findOne: (predicate: (record: T) => boolean) => Promise<T | undefined>;
findOneBy: (where: RecordWhere<T>) => Promise<T | undefined>;
```

- **What they return:** the first matching record in insertion order, or `undefined` when nothing matches. Like the other methods, they return copies, so changing the result doesn't change what's stored.
- **Name:** I called the second one `findOneBy` instead of `findBy`. In TypeORM-style libraries `findBy` returns an array, so this name avoids confusion if we ever add the array version.
- **How `findOneBy` compares:** it checks each field you pass with `===` and skips fields set to `undefined`. That suits strings, numbers and enums like `email`, `role` or `status`. Array or object fields never match, because `===` compares references, not contents.
- **Where the code lives:**
  - The interface change is in [repository.ts](libs/shared/src/repository.ts), along with two small helpers that both storage adapters share.
  - [memory-repository.ts](libs/shared/src/memory-repository.ts) and [file-repository.ts](libs/shared/src/file-repository.ts) each gain the two methods.
  - `RecordWhere` is exported from the shared package.
- **Tests:** new cases in the shared repository test suite run against both the in-memory and the file adapter. They cover the first match, no match, matching on several fields, a predicate that throws, and returned copies being independent.

The task doc said `libs/shared` would stay unchanged, so I updated it to record these additions as made at your request. Existing repository behaviour is unchanged.
