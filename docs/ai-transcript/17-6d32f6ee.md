**What the endpoint does:**
- **Who can call it:** admins only. Anyone else gets `403`, before the request body is read.
- **Allowed changes:** cancel a `pending` payment, or mark a `processing` payment `succeeded` or `failed`.
  - `failureReason` is required for `failed` and rejected for the other two.
  - Asking for `processing` or `pending` returns `400`, because the payment processor owns that step.
- **Invalid moves:** a change the current status doesn't allow, including cancelling twice, returns `409 invalid-status-transition`.
- **Simultaneous updates:** if another write lands at the same moment, the service re-reads the payment and checks again, up to 3 attempts in total. If the payment has already finished, the admin gets `409 invalid-status-transition` naming the real current status. Only if all 3 attempts hit a conflict does it return `409 version-conflict`.
