## Your folder split

Your NestJS-style split works, with one change. The `user/` folder should hold user **service functions** ("find a user", "create a user"), not HTTP endpoints. No roadmap milestone asks for `GET /users` or `GET /users/:id`. Those endpoints would also need the role guard from BE-02-03, which doesn't exist yet. So `user/` plays the part of NestJS's `UsersService` and `auth/` plays `AuthController` + `AuthService`. If you do want users endpoints, they'd get a new milestone (BE-02-05) after BE-02-03.

```
services/auth/src/
  user/   user.ts (model, unchanged), user.service.ts  ← findByEmail, findById, create
  auth/   auth.schema.ts, auth.service.ts, auth.controller.ts, auth.routes.ts, auth.openapi.ts, token.ts
  core/   password.ts  ← adds verifyPassword and a shared passwordSchema (8–72 bytes)
```

`auth.service` calls `user.service`, never the repository directly. `user.service.create` is the single place that checks email uniqueness. It runs the check and the insert through one in-process promise chain, so two registrations for the same email can't both succeed. The BE-02-01 follow-up called for this.

1. **JWT library:** `jose` 6.2.12. It's ESM-native, typed and has no dependencies. The alternative, `jsonwebtoken`, is CommonJS and needs `@types`. BE-02-03 will use the same library in `libs/shared`.

5. **Issuer and audience claims (`iss`/`aud`):** leave them out. The Decisions table lists only `sub`, `email` and `role`, and all services share one secret, so they add nothing yet.
